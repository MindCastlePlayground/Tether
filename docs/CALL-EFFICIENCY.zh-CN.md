# 减少 Agent 调用轮次：初步方案

[English](CALL-EFFICIENCY.md) · [回放设计](REPLAY-DESIGN.zh-CN.md)

2026-11-03。状态：方案探索；组合执行接口尚未实现。

## 结论

优先把“执行一个已知动作 → 等待明确条件 → 返回结果树”放进一次工具调用，再把稳定的业务步骤整理成回放片段。Agent 保留判断和分支，运行时承担轮询、分页和已确定的顺序操作。

需要分别统计模型往返、公开工具调用、Broker/CDP 请求、输出 token 和完成时间。一次工具调用可能仍包含很多浏览器请求；将 HTML 一次全部塞进上下文会减少调用数，却可能增加耗时和阅读成本。以下数字是调用路径推演，实际节省率待实验。

## 现有能力与可立即使用的方式

| 场景 | 常见路径 | 当前可用方式 | 公开调用变化 |
| --- | --- | --- | --- |
| 点击后查看当前页面 | click → snapshot | click 携带 `observe:{}`，复用 `after.tree` | 2 → 1 |
| 等待结果出现 | Agent 多次 snapshot 后判断 | 一次 wait/assert，由服务端轮询 | N → 1 |
| 树中缺少必要属性 | 反复读取相同简要树 | 转 html，按 captureId 读取稳定快照 | 避免无效重试 |
| 大页面读取 | 每页结果交给模型决定下一页 | SDK 脚本按 nextOffset 循环，拼接后提取任务所需内容 | 模型介入可降为 1 次；RPC 数保持分页数 |

动作后的 `after.tree` 是当时观察到的状态；等待异步保存完成仍需明确条件。`snapshot` 是简化的无障碍树，`html` 是主文档序列化，两者的信息范围不同。HTML 分页循环可在已有代码执行环境里完成；纯 MCP 客户端仍需逐页调用。原始 HTML 可能含凭据或隐藏数据，脚本应返回任务需要的内容。

## 下一步建议：动作、等待、结果合并

在现有 action 的可选参数中增加条件等待，复用 `Conditions` 与现有 `observe` 结果结构。先支持 click/fill/navigate 的单动作组合，避免同时建立另一套动作执行器。

- 输入：现有动作参数、可选等待条件、可选结果树范围；参数名称在实现前确定。
- 执行：仍走 Broker 授权、seq 去重和页面检查；动作只派发一次，轮询只读条件；条件满足后返回树。
- 输出：分别保留动作 `sideEffect`、条件是否满足及耗时、结果树或观察错误。条件超时仍应报告已经发生的动作，保留后续排查依据。
- 超时：组合调用的总时限须协调 SDK 25 秒、Broker 转发 20 秒、条件等待最多 15 秒等现有预算。预算耗尽后停止后续步骤；已经派发的动作按结果不确定处理。
- 并发：同一会话写操作继续串行；JavaScript 对话框处理保留可解除阻塞的独立通道。

在目标和条件都已知的情况下，click → wait → snapshot 或 navigate → wait → snapshot 可从 3 次公开调用变为 1 次。发现陌生页面、选择业务分支时继续交回 Agent。

## 与回放共用可复用片段

第二步支持受约束的步骤列表，沿用[回放设计](REPLAY-DESIGN.zh-CN.md)中的动作、输入、断言与结果模型。已知选择器的“填写三个字段 → 提交 → 等待成功 → 读取结果”可从 6 次调用合并为 1 次运行请求。遇到定位歧义、断言失败或结果不确定时停止，并返回失败步骤、已完成步骤和最后的树；禁止自动从头重做提交动作。

个人使用可直接保存和调用常用片段；企业团队可以沿用仓库 PR、测试数据和环境参数管理。片段复用授权会话，不扩展浏览器权限。用户已有的确认和审批仍在原业务决策点执行。

暂缓给普通 Broker 增加任意 JavaScript 执行入口。已有沙箱和 SDK 可用于确定性循环；通用代码执行涉及新的文件、网络和凭据边界，需要单独设计。

## 如何验证收益

使用相同模型、同一固定页面和相同任务输入，对照当前原子调用与拟议组合调用：异步保存、三字段表单、包含隐藏属性的大页面、一次导航后继续操作。比较任务完成率、模型往返数、RPC 数、输出 token、总耗时及重复副作用次数；分别保留成功和失败样本。先证明成功率与副作用行为保持一致，再比较轮次和延迟。当前阶段不设置未经测量的百分比承诺。
