# Tether internationalization

[简体中文](I18N.zh-CN.md) · [Project overview](../README.md) · [Popup guide](../prototype/README.md)

The extension ships Chrome locale catalogs for English (`_locales/en`) and Simplified Chinese (`_locales/zh_CN`). The popup reads Chrome's UI language with `chrome.i18n.getUILanguage()` and renders from those message catalogs; the manifest's extension name and description use `__MSG_...__` references so Chrome can show the matching language in extension surfaces.

The popup offers three choices: follow the browser (`auto`), English (`en`), and Simplified Chinese (`zh-CN`). The selected value is saved in `chrome.storage.local`; an explicit language overrides the browser language on later popup opens, while `auto` follows it. With no saved value, the popup also follows the browser language. User-facing strings, including accessible labels and status/error text, come from the locale catalogs; protocol values, storage keys, and internal identifiers remain language-neutral. The on-disk Chrome locale folder is named `zh_CN`, while the saved popup preference is `zh-CN`.

## Adding or changing a language

1. Add a locale catalog under the extension's `_locales/<locale>/messages.json`, preserving each message key and placeholder definition used by the existing catalogs.
2. Translate the message values, including descriptions, accessible names, and status text. Keep protocol identifiers and code examples unchanged.
3. Import the new catalog in `prototype/extension/i18n.js`, extend `Locale.Catalogs`, `Locale.normalize()` and `Locale.valid()`, then add the language to the popup's explicit language choices only if it is intended to be user-selectable. Keep the stored preference value stable and locale-specific.
4. Update the manifest's localized name/description messages where needed.
5. Update both this page and [I18N.zh-CN.md](I18N.zh-CN.md) when the selection or persistence behavior changes.
6. Review local links and compare message keys/placeholders across all locale catalogs. Runtime/build validation belongs in the implementation change; this guide itself is not evidence that such checks were run.

Chinese browser locales (including zh-TW) currently use the Simplified Chinese catalog; other unsupported languages fall back to English. The toolbar title and extension metadata follow the browser locale independently of the popup preference.

The preference controls popup presentation only. It does not change authorization policy, broker protocol, or browser language settings.

## MCP and installation scripts

The root installer uses `--language en|zh-CN` for its help/status messages and the generated MCP configuration. With no option, it follows the Node system locale; it does not read `BB_LANGUAGE` as its language selector. See [installation](INSTALL.md) and [installer verification](INSTALL-VERIFICATION.md). The popup preference, installer option and MCP environment variable are independent settings.

Set `$env:BB_LANGUAGE = 'zh-CN'` or `$env:BB_LANGUAGE = 'en'` in PowerShell before starting MCP or running installation scripts. For MCP clients, add `"env": { "BB_LANGUAGE": "zh-CN" }` alongside `command` in the MCP server configuration. With no override, MCP uses the Node system locale, Python setup uses its system locale, and PowerShell uses the current culture. Unknown explicit values fall back to English. API names, JSON fields, error codes and diagnostic evidence are not translated.

The launcher generation script now forwards `BB_LANGUAGE` to its child process. Existing `.local/mcp.exe` launchers generated before this change must be regenerated: with the MCP client stopped, remove only `.local/mcp.exe` and run `powershell -ExecutionPolicy Bypass -File scripts/launchers.ps1` from `prototype/`. The script generates missing launchers without starting them. This does not regenerate credentials or require starting Broker.

## Verification

Run `npm run docs:check` from the repository root to check every published Markdown document for an English/Simplified Chinese pair, reciprocal language navigation, matching heading levels, tables and code-block structure, and valid local links. Review translations for matching meaning when editing either language; structural checks cannot establish semantic equivalence. Keep commands, RPC names, JSON fields, paths and evidence boundaries aligned; translate explanatory code comments as well as prose. `SKILL.md` alone carries discovery frontmatter; `SKILL.zh-CN.md` is its translated reading copy. Local ignored migration notes and diagnostic logs are not published documentation.

Run `npm run build`, then `node --test --test-isolation=none test/i18n.test.mjs test/extension.test.mjs` from `prototype/`. Run `node scripts/brand-preview.mjs` for isolated headless Chrome checks of both languages, preference persistence, automatic language detection, authorization actions, tab selection, error states and layout. It uses a mocked extension runtime and never starts Native Host or Broker. Reports and screenshots are in `assets/`; this does not replace acceptance of the real installed extension.

On 2026-10-11, the build, 22 isolated unit/simulation tests, both popup language flows, and actual MCP stdio initialization/tool listing in both languages passed. Python and PowerShell syntax checks passed. `node scripts/i18n-smoke.mjs` repeats the MCP check using existing `.local/agent.json` without calling the bridge. The installed extension and existing launcher executables were not reloaded or rebuilt; Broker remained stopped.
