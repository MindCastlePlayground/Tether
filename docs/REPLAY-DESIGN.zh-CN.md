# 回放大功能设计

[English](REPLAY-DESIGN.md)

## 目标

为 Tether 增加可复用、可检查的浏览器回放能力。回放由一组浏览器动作、输入和断言组成，可在新授权页面中执行。场景定义与录制分离，网络行为由每次运行明确选择。本文仅描述设计，不增加实现，也不表示现有系统已支持回放。

## 现有基础

- Tether 通过 `requestSession`/审批授权浏览器访问，随后提供页面操作和 `release`。变更调用使用串行递增的 `seq`；调用超时后，网站侧结果可能处于不确定状态。
- 沙箱通过 `sandbox_eval` 提供 Playwright 的 `context`、`browser` 和 `chromium`；其 Profile 会持续保留至显式重置。需要隔离的测试应使用新 context/Profile 或专用临时浏览器状态。
- 网络 SDK 可针对会话页面执行 start/list/detail/body/stop/clear 采集。它记录开始采集后的流量，是检查工具，不是 HAR 回放工具。
- MinimumWebAuto 提供了值得参考的简洁编写方式：`site(url)`、`fill`/`click` 等易读动作、`see` 断言、可链式调用的局部视图，以及显式临时 Profile。可借鉴清晰度和隔离思路，不复用其 Python API 或行为。其文档中的接口包括可见文字操作、`Target.css`、表格/列表辅助方法、`Profile.TEMP`，以及托管/监控/热运行模式。

## 场景模型

将可复用场景保存为带版本、由人维护的定义，包含稳定场景 ID、标题、起始 URL、可选视口/语言、步骤顺序和声明式输入。定义使用普通的版本控制文件（实现阶段再确定格式）；不额外生成无消费者的清单或第二套状态库。

每一步只表达一个动作或断言。首批动作覆盖导航、按可见文字或角色点击、用具名输入填写、选择/勾选/取消勾选、等待定位器/状态及截图。首批断言覆盖 URL、可见文字、定位器数量/状态和明确选出的页面值。优先采用语义定位器；CSS 作为显式备用手段。断言报告观察到的值，并在失败步骤准确停止。不要仅凭点击或网络响应推断业务成功。

把可复用动作保存为具名场景片段，声明输入和输出，以便组合常见登录、导航和准备流程，避免复制步骤。断言与动作分开，预期值可供审阅。参数集中在声明式输入表中，标注类型、必填/默认状态和秘密标志；运行时从调用者提供的受保护来源读取。场景文件和 trace 中不得内嵌凭据、Cookie、令牌或私有测试数据。

## 录制与回放分离

录制是编写辅助工具，用于捕获候选 UI 动作、定位器依据和可选诊断信息。它生成待审草稿，不会自动发布为可复用场景。作者应将草稿整理为稳定的语义定位器和明确断言，标记输入，并在保存前清除秘密。

回放执行调用方选定的场景。个人使用时可直接编辑、运行；企业团队可沿用现有 PR 流程评审变更。运行器记录步骤结果，并按产物策略附加截图/trace。Trace 用于诊断，场景定义用于执行。Playwright Trace Viewer 可展示动作、DOM 快照、截图、控制台和网络活动；HAR 用于请求匹配与响应填充。

## 网络模式

网络模式保存在场景中，单次运行可覆盖：

1. **真实网络**：访问实际目标并使用正常网络。会改变网站状态的动作可能产生真实影响；场景和运行请求应明确展示这一点。结果不确定时不得自动重试。
2. **Mock 网络**：使用经过审阅的 HAR/API 固定数据，获得可重复的读取结果和受控响应。优先采用最小数据集；保存前清理认证信息、Cookie、个人数据和不必要的正文。未匹配请求按明确策略处理（默认失败；只有场景声明主机/路径可安全直连时才允许放行）。
3. **混合网络**：模拟声明的路由，其余请求走真实网络。场景/运行记录列明路由规则和允许直连的来源；未列明的请求应失败，避免意外访问生产环境。

网络采集在三种模式下都可用于诊断，但 Tether 当前的 `network` 方法只观察采集到的流量。HAR 路由拦截/回放需要单独实现 Playwright 沙箱能力；开发并验收之前，不能将其描述为现有功能。

## 凭据、兼容性和不确定结果

运行时从受保护配置或获准的秘密提供方读取凭据。步骤日志、错误、截图（在可行范围内）和导出的 trace 均对秘密输入脱敏。浏览器存储、请求头、正文、URL、trace/HAR 文件都按潜在敏感数据处理；实现时将其保存在配置的本地任务存储中，并支持保留期限/清理策略。

场景格式版本与运行器兼容版本分别管理。遇到不支持的格式版本时给出明确错误。运行元数据记录 Tether 运行器版本、浏览器版本、场景修订、网络模式和固定数据版本。格式变化使用明确迁移；不得猜测缺省字段或静默改变旧场景含义。定位器或协议行为有要求时，应声明或固定浏览器/固定数据条件。

同一页面上的变更操作串行执行。操作请求超时或派发后连接中断时，将该步骤标记为 `unknown`，直到断言或人工检查确认页面结果。不要自动重放该操作：它可能已提交表单、创建记录、付款或发送内容。只有后续只读观察能安全确定状态时才继续，否则停止并保留诊断证据。释放会话会结束 Tether 授权，但不会撤销网站侧效果。

## 隔离与验收

自动验收默认使用可丢弃浏览器状态和本地固定页面。每次运行使用新 context/Profile、空存储及隔离的下载/输出目录；并行运行不得共用 Profile、页面或可变固定数据。复用已登录的持久 Profile 属于用户明确要求的真实任务操作模式，不作为测试默认值。清理运行产生的状态时，不影响 `/data` 中无关内容。

验收应证明：场景能由可复用动作和断言组成；声明式输入可在不写入场景定义的情况下解析；秘密值不会进入日志/产物；同一场景在 Mock 固定数据上稳定通过；真实网络和混合模式能列清所有直连目标；未匹配 Mock 请求遵循策略；断言失败能定位到具体步骤；并行运行彼此隔离；不兼容格式会明确失败；变更调用中断时标记为不确定且不自动重放。录制生成草稿与回放执行应分别验收。

## 实施顺序

1. 确定场景格式、最小动作/断言词汇、输入来源约定、产物处理和明确的网络模式语义。
2. 在本地固定页面上构建只读运行器，使用临时 context；加入步骤结果和断言。
3. 加入具名可复用片段和运行时输入解析，包括秘密脱敏。
4. 加入录制转草稿及编辑、保存、运行流程；团队有评审要求时沿用现有代码评审。
5. 加入 Mock HAR/API 路由和未匹配请求策略；Mock 验收后再加入真实/混合路由控制。
6. 加入版本兼容、不确定状态、诊断产物策略，并针对这些行为做专项验收。
