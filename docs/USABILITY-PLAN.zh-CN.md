## 一、背景与目标

Tether 目前已经具备以下能力：

- 页面快照（snapshot）：支持 `scope`、`depth`、`maxChars` 和 ref。
- 元素定位（locate）：支持按文本、角色加名称、选择器、ref 定位，最多返回 10 个候选。
- 唯一性检查：动作前进行唯一性检查；已识别的歧义会拒绝执行，并返回 `sideEffect:none`，但下文所列截断检查仍可能误判。

日常使用中仍有三类问题：

1. **定位可能偏离范围**：源码中的文本回退可能越出原范围；本轮未实测发生频率。
2. **大页面难以浏览**：候选列表缺少上下文，同名按钮无法区分；整页快照太长，又没有目录可以逐块查看。
3. **结果难以确认**：动作完成后，需要再手动拍一次快照才能看到发生了什么。

本方案分三批解决。顺序原则是**先保证不点错，再改善找得到，最后改善看得见**。

## 二、当前行为与拟改对比

| 场景 | 当前 | 拟改后 |
|---|---|---|
| 带父范围的选择器（如 `.modal button:has-text("OK")`）找不到元素 | 文本回退可能查整页，点到弹窗外的 OK | 回退结果必须满足原选择器的全部限制；无法证明这一点时，只返回候选，不执行 |
| 匹配很多元素，只有靠后的一个可见 | 可见性只检查前 20 个，可能误判为唯一 | 检查完整时按结果判定；检查不完整时拒绝执行，绝不把截断结果当作唯一 |
| 导航后继续使用旧 ref | 存在误命中新页面同名 ref 的风险（尚未复现） | ref 带有文档代次，跨文档导航后返回"已失效" |
| 同名按钮出现在多个区域 | 候选已有角色、名称、标签、选择器等信息，但缺少所属行或区域的上下文 | 候选附带所在行、列表项、对话框或区域等上下文，以及可直接用于动作的 ref |
| 大页面 | 只能整页查看，或手写 scope | 先看目录，再按区域展开 |
| 动作后确认结果 | 需要另拍快照 | 可选在同一次调用中附带有界观察 |

依据来自源码阅读（未运行测试），涉及 `Rewrite.all` 的文本回退、`visible()` 的前 20 个限制、`unique()` 返回未校验选择器，以及 `describe` 与 `visible()` 可见性口径不一致。

## 三、批次 A：定位正确性与 ref 生命周期

本批修正定位行为并调整 ref 格式，不新增独立工具。ref 的协议校验、SDK、MCP 说明与使用文档须同步更新。

### 1. 回退不越出原范围

本方案不实现通用选择器解析器。规则如下：

- **原位改写**：如 `:contains` 改为 `:has-text`。只有确认语义等价时才保留这一路径。
- **回退结果必须满足原目标的全部限制**，包括父范围、标签和属性。例如 `input[name=q]` 的回退结果不能是同一区域里的 `button`。"范围相同但类型不同"不算正确。
- **复杂选择器**：如果原选择器含组合符、XPath 谓词等，且无法证明回退保持原范围，则不做语义放宽。此时返回 `selector_not_found`，并附上候选供用户确认。
- 用户需要限定范围时，优先使用明确的 scope 约束（见批次 B）。

### 2. 可见性口径一致

- 计数与描述统一使用引擎的可见性语义。可以先按可见性过滤，再计数。
- 资源受限、无法检查全部匹配时，返回"检查未完成"并拒绝动作。本方案不设固定上限阈值，具体上限以实测为准。
- 检查完整且确认只有一个可见元素时，可以正常执行。
- `unique()` 未能验证唯一时，候选必须明确标注"未验证唯一"。

### 3. ref 生命周期

导航后旧 ref 误命中新元素，是**尚未复现的风险**。本批将它作为生命周期要求来实现，并配套验收：

- 对外返回的 ref 改为**带代次的不透明标识**，具体编码不在本文档固定。如果服务端记录了代次，而请求仍使用裸 `e12`，服务端无法判断它属于哪个文档，所以代次必须体现在 ref 本身。
- **同一文档内**，同一元素的 ref 保持稳定。
- **跨文档导航后**，旧 ref 返回 `ref_stale`，不再按角色或名称回退到新页面的元素。
- **SPA 仅 URL 变化**：如果原元素仍在页面中，ref 不强制失效。如果元素已被替换，不得仅凭全页同名就静默换成另一个目标。
- 旧映射有界维护，不无限累积。

## 四、批次 B：候选上下文、统一范围、按区域查看、可执行错误指引

### 1. 统一范围参数

snapshot 和 locate 共用两个范围参数：`scope`（选择器）和 `scopeRef`（来自快照或目录的 ref）。两者互斥，同时提供会报参数错误。click/fill 不增加范围参数，直接使用 locate 返回的 ref 即可。

### 2. 候选上下文

- 每个候选附带**最近的有意义容器**（row、listitem、dialog、region），必要时补充关联标题，而不只是按钮自身的名称。
- 如果页面没有语义结构，就如实缺省上下文，不编造名称。
- 上下文有长度限制，但会保留身份线索，例如行内的订单号或用户名。
- 候选的 ref 在发出时就可以直接用于动作。精确选择器无法验证唯一时，会明确标注，不宣称已经唯一。

### 3. 候选数量

- 默认最多返回 10 个候选，同时报告总数、本次显示数和是否截断。
- 截断时引导用户用 scope 收窄范围。区域本身很大时，还可以在区域内再按文本或角色筛选。
- 本批**不做分页**。原因是首尾哈希无法检测中间的变化，分页是否需要，等有实际场景再决定。

### 4. 页面目录

- `outline` 从**一次**页面语义快照中提取区域入口，用户再用 `scopeRef` 展开某个区域。
- 原始 ARIA 树可能省略没有名称的区域，所以不保证每个 DOM 节点都有目录项。这类区域仍可用 `scope` 选择器查看。
- 目录优先展示较高层区域的 ref；子区域过多时保留其父区域入口，展开父区域后再查看下一层。目录也受长度限制；预算小到容不下入口时，应明确提示增大 maxChars 或提供 scope，不返回无法操作的“另有若干区域”。
- 快照返回的 refs 计数仅统计本次实际输出的 ref，目录不混入未展开子树的 ref 数量。

### 5. 可执行错误指引

错误信息给出下一步可以做什么。例如歧义时提示"用 scopeRef 限定区域"，ref 失效时提示"重新拍快照"。

## 五、批次 C：按需操作后观察

- 只有用户主动开启 `observe` 时才生效。动作完成后做一次有界观察，报告以下证据：URL、是否导航、局部内容、新出现的提示文字。
- 只报告看到的事实，不推断业务是否成功。只有取得前后观察证据时才称“新出现”；没有前置证据时，仅称“当前看到”。
- 不保证能捕捉所有短暂出现的 toast。等待时长以实测为准，不承诺固定 1 秒。
- **观察失败**：动作结果保持不变，也不重复执行写操作。
- **动作本身为 `outcome_unknown`**：即使观察成功，也不改为 `applied`。
- **导航导致观察用的 scopeRef 失效**：报告失效，不放宽到其他区域。
- fill 默认不回显填入的值，避免泄露敏感字段。

## 七、接口字段汇总（拟议）

| 字段 / 返回值 | 适用 | 说明 |
|---|---|---|
| `scope` / `scopeRef` | snapshot, locate | 二者互斥 |
| `outline` | snapshot | 返回区域目录 |
| `count` / `shown` / `truncated` | locate | 总数、本次显示数、是否截断 |
| 候选 `ref` / `context` / `selectorUnique` | locate | 可直接用于动作；`selectorUnique:false` 仅表示选择器未验证唯一，ref 仍标识候选元素 |
| `observe` | click, fill | 可选，开启操作后观察 |
| `observed` / `after` | click, fill | 观察结果，不影响 `sideEffect` |
| `ref_stale` | 所有 ref 输入 | 跨文档导航或元素被替换 |
| 可见性检查未完成 | 动作 | 拒绝执行，`sideEffect:none` |

## 八、兼容与迁移

- 新增范围、目录和观察参数均为可选。现有方法保留，但批次 A 会收紧自动回退，并调整 ref 格式；依赖旧回退行为或校验旧 ref 格式的调用方需要迁移。
- ref 改为带代次的格式后，**并非所有旧 ref 都能自动兼容**。旧裸 ref 不自动映射到新格式；升级后调用方需重新获取快照，并使用返回的不透明 ref。新实现不得把旧裸 ref 跨新快照或导航映射到新目标。
