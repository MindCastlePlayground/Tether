# Verification summary

[简体中文](VERIFICATION.zh-CN.md) · [Runtime guide](README.md)

Updated: 2026-10-22. This public summary consolidates the v1.2.0 locator verification (2026-10-22), the v1.0.0 release verification (2026-10-18), installer v1.1.0 verification (2026-10-19), and earlier browser acceptance. It describes recorded checks, not a new test run.

| Area | Recorded result | Boundary |
| --- | --- | --- |
| Build and automated checks | v1.0.0: TypeScript build, 38 installer tests, 61 runtime/extension tests, and 5 Python client tests passed. Installer v1.1.0: 44 tests passed. | Test suites cover different layers; passing tests alone do not establish browser acceptance. |
| Install and upgrade | Fresh isolated installation and upgrade from v0.1.1 completed. Existing runtime files retained their recorded SHA-256 hashes. v1.1.0 upgrade, repeat/forced installation, fresh tarball install, and standalone upgrade completed. | Windows host only. Installer checks used registration opt-out; browser loading and live page RPC were not repeated for the v1.1.0 installer change. |
| MCP and Native Messaging | The installed MCP executable started from another working directory and exposed 12 tools in English and Simplified Chinese with empty stderr. The v1.0.0 release checks exercised Native Messaging and lifecycle controls in real Chromium. | Client startup and transport checks do not prove every browser or agent host works. |
| Browser page control | Earlier real Chrome runs completed authorized observe, fill, click, navigation, and release flows through Node SDK and MCP, including a model-driven website flow. | Edge, Python SDK page actions, every tool, and all authorization/lifecycle cases were not covered. |
| Element snapshot and locators (v1.2.0) | 104 runtime/extension tests (14 locator tests against headless Chrome) and 44 installer tests passed. `scripts/locator-e2e.mjs` ran in isolated Chromium with the real extension, a temporary Native Messaging host and Broker: `snapshot` refs, a ref click on `button > div > span`, XPath `text()` rewrite, nested-text fallback, refusal of an ambiguous selector with `sideEffect:"none"`, a click on a `locate` candidate, and fill by label text. The installed runtime was upgraded and its MCP exposed 14 tools. | The user's own Chrome profile did not reconnect to the upgraded Broker during this run, so live MCP use in that profile was not repeated. Two Python transport tests fail in the development checkout with a self-signed certificate error on unchanged code as well. |
| Network and isolation | Runtime checks covered TLS/pin validation, authentication, session/page authorization, and limited endpoint snapshots. | No second LAN machine was tested. Snapshots are not packet capture and do not establish zero external traffic for the entire browser profile. |

The evidence is summarized from [release v1.2.0](../docs/RELEASE-v1.2.0.md), [release v1.0.0](../docs/RELEASE-v1.0.0.md) and [installer verification](../docs/INSTALL-VERIFICATION.md). Checks were performed on Windows with isolated test data. Results do not establish cross-platform support, all-browser compatibility, or complete zero-egress behavior. See the [runtime guide](README.md) for operating boundaries.
